# ADR 0003：运行态放内存，多实例前必须先补四件事

- 状态：已采纳（首版）
- 日期：2026-11-16
- 相关：架构书第 12.2、13.2 节

## 背景

run 状态包含工作副本（可能含简历全文）、事件序列与待用户决策。它需要被 SSE 读取、
被恢复执行、被 TTL 清理。选内存还是选 Redis，决定了能不能多实例。

## 决定

首版用**有界内存**实现（`adapters/store_memory.py`）：

- 最多 500 个 run，单 run 事件最多 400 条（`JIANMIAN_MAX_EVENTS`）；
- run 默认 30 分钟过期（`JIANMIAN_RUN_TTL`），后台任务每 60 秒真正删除；
- 进程重启则活动 run 失效——前端草稿仍在 localStorage，用户重建任务即可；
- 端口 `RunStore` 只暴露 `create/get/update/delete/find_by_idempotency/purge_expired/stats`。

## 换共享存储时必须同时补上（缺一不可）

1. **run 所有权**：`sessionId` 与请求会话比对（现已做），共享存储下还要防跨实例串号；
2. **执行租约**：同一 run 只能有一个 worker 在跑，租约需带过期与续租，否则恢复会双跑；
3. **事件序列**：`seq` 必须由存储端单调分配，不能用"读-改-写"，否则并发写会撞号；
4. **确认 CAS**：一条确认只能恢复一次；用 `proposalId + 状态` 做条件更新，
   而不是"先查再写"。

只换存储、不补这四件事，会得到"偶发重复扣费/重复应用提案"这类最难查的故障。

## 代价

- 单实例，重启丢活动 run；
- 进程内 `asyncio` 任务不能宣传成持久队列；
- 长 OCR 任务首版走"提示 + 手动校对"，不做后台 worker。

## 检验方式

`tests/test_api.py::test_expired_runs_are_purged` 验证清理是真实行为，不是隐私声明；
`services.purge()` 同时回收导入暂存与面试会话。

# 0008 界面：对话做主页，工作台只做编辑

- 状态：已采纳
- 日期：2026-11-16
- 影响面：`apps/web/` 全部（`index.html`、`css/app.css`、`js/app.js`、`js/history.js`、`js/editor.js`、`js/chat.js`）

## 背景

第一版界面是三栏工作台：左边表单、中间 A4、右边助手，起始页是一张立体纸。
它把「能力」摊开得很全，但带来三个问题：

1. **入口太散**。导入、岗位、面试、档案四个功能挤在顶栏 tab 里，和「编辑简历」平级，
   用户一进来不知道从哪儿开始；
2. **主页在卖概念，不在干活**。起始页把大量预算花在纸的质感、光斑、扫描线上，
   而用户真正要做的第一件事只是「说一句话」；
3. **对话只是一块侧栏**。多轮修改时，对话被压在 400px 里，提案卡片挤成窄条，
   而对话恰恰是这个产品的主链路。

## 决策

### 1. 主页 = 对话页，屏幕上只有三样东西

一句主张（「好的简历，只用一面」）、一个输入框、一个箭头。没有插画、
没有渐变光斑、没有装饰线条。发送键是描边圆形箭头，不用蓝色实心块。
极简不是把装饰调淡，而是不放装饰。

### 2. 左侧固定栏：任务在前，历史在中，设置在后

```
面试 / 调研 / 工作台 / 档案
新对话
─────────────
对话历史（按最近说话时间排序）
─────────────
个人设置
```

四个入口对应四种**任务**，而不是四个功能面板。工作台是其中之一，
它只负责编辑——不承担面试、调研、档案。职责单一换来的是左栏可预测：
点「面试」永远进面试，不会突然弹出简历字段。

### 3. 工作台保形，但把「AI 润色」换成「让智能体修改」

工作台沿用原设计：左侧模块库（编号 01–08 的网格）+ 已编辑列表，
中间 A4 真实排版，右侧「编辑 · 某一段」的字段面板。
唯一的改动是右侧底部那块：原来的「DeepSeek 智能润色」按钮，
换成**让智能体修改**——

- 输入一句要求 → 跳到对话页，带着「把「选课系统」这一段写得更专业」这句上下文发出去；
- 提案回来后仍然逐项确认，视觉上没有任何"背着用户改"的路径。

为什么不在工作台里内嵌一个迷你对话框：那会让工作台同时承担"编辑"和"对话"两种心智，
而且提案需要足够的横向空间展示 before/after。跳回对话是**把任务交给更适合的界面**，
不是"退出编辑"。

### 4. 对话历史只存文本，不存文档

`js/history.js` 存 `{id, title, updatedAt, messages[]}`，消息只有纯文本与卡片标记。
简历主数据仍在 `js/state.js` 的 Store（localStorage）。

这带来一个明确的产品语义：**一个人，一份简历，很多次讨论**。
换一段对话不会换一份简历——这也是本产品与"多文档编辑器"的分界。

提案与澄清不做历史回放：提案有 30 分钟有效期，回放一个已失效的提案比不显示更糟。
历史里只保留"说过什么"，以及一张指向当前简历的卡片。

### 5. 空简历上的第一句话默认按「生成简历」处理

新用户不该先被反问一轮。`intents.classify` 在**简历没有任何内容**时，
即使没命中任何关键词也归到 `build`；`build_check_materials` 在素材过短时
不逼用户补充，而是退到结构模板（占位文字，不编造经历），并在提案摘要里
明确写「先给你一份结构模板（占位内容请替换成真实经历）」。

这条规则的边界很清楚：**只对空简历生效**。一旦简历里有了内容，
模糊指令仍然走澄清——不能让"默认生成"变成"默认乱改"。

## 代价

| 代价 | 说明 |
|---|---|
| 多一次跳转 | 工作台里让智能体改，要跳回对话页；换来的是提案有足够空间、职责不混 |
| 历史不存提案 | 回到旧对话看不到当时的 diff，只能从版本号推断发生了什么 |
| 极简牺牲信息密度 | 主页没有功能宫格，新用户需要点一次左栏才知道还有什么 |

## 被否掉的方案

- **保留三栏、把对话挪到左边**：对话仍然被挤在窄栏里，提案 diff 读不了。
- **主页放功能宫格（面试/调研/档案各一张卡）**：把"任务的入口"和"任务本身"混在一起，
  而且主页第一眼该看到的是产品承诺，不是功能清单。
- **起始页保留立体纸**：它讲清了"一页"这件事，但代价是每次打开都要等一段动画，
  且与"对话是主页"的新结构冲突。纸的隐喻被一句话接管。

# ADR 0004：事实守卫的三层结构与它的边界

- 状态：已采纳
- 日期：2026-11-16
- 相关：架构书第 7.3、10.1 节

## 背景

"不要编造"是产品承诺，但"编造"很难被完全形式化地判定：数字不变也可能改变因果，
"参与"改成"主导"一个数字都不用加。必须在"能确定性拦住"和"只能提示"之间划清界线。

## 决定

字段先分级（`domain/modules.py`）：

| 策略 | 含义 | 典型字段 |
|---|---|---|
| `locked` | AI 无写入权限，只能由人确认 | 姓名、电话、邮箱、学校、专业、学历、公司、职位、起止时间、奖项名称 |
| `guarded` | 允许改写表达，但事实 token 必须守恒 | 项目详情、工作内容、主修课程、技能清单、获奖级别、自我评价 |
| `open` | 纯表达 | 大段描述中的修饰语（仍受 `guarded` 检查约束） |
| `asset` | 二进制资源，只允许人工上传 | 肖像 |

再叠三层检查：

1. **字段级白名单**：`locked` 字段不出现在 `ai_fields` 里，工具层直接拒绝；
2. **确定性 token 守恒**（`domain/facts.py`）：年份/数字/百分比/金额，新增或删除都判失败，
   除非该 token 在事实库里有来源（`allowed_tokens`）；
3. **辅助提示**：语义升级（参与→主导）、长度膨胀只产生 `warning`，交给用户对照原文确认。

## 边界（必须说清）

- 第二层只保证"数字与日期不变"，**不保证语义不变**；
- 第三层不是形式化证明，只是提示；
- 因此界面始终保留原文对照、事实来源与人工确认，不宣称"完全消除幻觉"。
- 事实提取（`extract_facts`）默认 `status="candidate"`，用户确认后才进入长期档案，
  面试表现**不会**自动变成"熟练某技术"的能力事实。

## 代价

- 一些合理的改写会被拦（例如把"服务 300 名学生"改写成"支撑一个 300 人的教学场景选择"仍会过，
  但"300 人同时在线选课"若原文没有"同时在线"就可能触发语义提示）；
- 用户需要多一次确认，交互成本上升。

## 检验方式

`tests/test_domain.py` 中：新增数字被拦、删除数字被拦、`locked` 字段不可写、
整批失败不产生部分写入；`tests/test_workflows.py::test_edit_run_keeps_numbers` 验证改写后 `300` 仍在。

> 注：测试期间发现年份正则 `(19|20)\d{2}` 会把年份截成 `"20"`，导致"2025→2026"的改动不被拦截。
> 已改为非捕获组 `(?:(?:19|20)\d{2})`，并保留用例防止回归。

# ADR 0006：模型适配与密钥隔离

- 状态：已采纳
- 日期：2026-11-16
- 相关：架构书第 8.3、13.1 节

## 背景

"能调通模型"和"能安全地给别人用"是两件事。历史上最常见的漏洞是：浏览器把 `base_url` 和 `apiKey`
一起传给服务端，服务端照单全收，于是项目变成了任何人都能白嫖的模型代理。

## 决定

1. **统一端口** `ModelProvider.generate(ModelRequest) -> ModelResult`：
   结构化结果、用量、`finishReason`、可重试错误、能力表（native tool calling / JSON mode / vision / 流式）；
2. **模型名白名单**：请求里的 `model` 必须落在 `config.ALLOWED_MODELS`，否则被服务端覆盖；
3. **Base URL 不可由浏览器指定**：只来自服务端环境变量（部署管理员配置）；
4. **Key 的三条路径**都只进内存：
   - 站长 Key：`JIANMIAN_OWNER_KEY`；
   - 用户 BYOK：请求头 `x-jm-byok`，**不进 JSON、不进事件、不进日志、不写 localStorage**；
   - 无 Key：`JIANMIAN_MODEL_PROVIDER=mock` 走离线确定性适配器；
5. **BYOK 走不计费通道**，站长 Key 走"预算租约"，预占 → 调用 → 按实际用量结算，
   失败退还租约。重试也计入预算；
6. **超时与重试**：单次 45 秒；仅网络/429/部分 5xx 带抖动重试；参数、权限、事实校验失败不重试；
7. **截断即失败**：`finish_reason=length` 明确标记，不尝试应用半截 JSON；
8. **用量待结算**：超时可能已被上游计费，标记 `usagePending`，不承诺"恰好一次计费"。

## 为什么 mock 是默认档

课程演示不该被 Key 卡住，也不该为了演示把简历发给第三方。mock 适配器的定位不是"假装有模型"，
而是把**可规则化**的部分确定性做掉：只从材料里抽取真实存在的实体，润色只做安全变换
（删套话、统一标点、动词开头），需要真正语义判断时明确降级。因此它天然满足事实守卫。

## 代价

- 真实模型质量明显更好，切换需自备 Key；
- mock 的"改写"偏保守，用户可能觉得润色幅度小——这是有意的取舍：宁可少改，不可编造。
- 推理型模型（`deepseek-reasoner`）成本更高，默认用 `deepseek-chat`。

## 检验方式

`tests/test_security.py` 的脱敏用例；`tests/test_api.py::test_config_exposes_no_secrets`
断言配置响应里没有 `owner_key` / `sk-`；`application/container.py::model_for` 是唯一的 Key 入口。

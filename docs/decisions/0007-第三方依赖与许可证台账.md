# ADR 0007：第三方依赖与许可证台账

- 状态：已采纳
- 日期：2026-11-16
- 相关：`requirements.txt`、README 第 10 节

## 背景

作业交付物要能被别人（老师、同学、未来的自己）拿走就跑。这意味着两件事必须写清楚：
**装了哪些东西**、**每个东西的许可证允不允许这样用**。顺带还有一个更现实的问题——
依赖越少，跑起来的概率越高。所以这份台账同时是"依赖预算"的账本。

## 决定

1. **运行时依赖只保留 7 个直接依赖**，其余全部自己写或用标准库；
2. 每个直接依赖必须说清**为什么需要它**、**不用会怎样**；
3. **LangGraph 是可选依赖**：装了就用来跑同一份图定义做对照，没装自动回退自研引擎，
   核心功能不因缺它而不可用；
4. 前端**零 npm 依赖**：12 个原生 ES 模块，直接由浏览器加载，无构建步骤；
5. 依赖**上界锁定**（如 `fastapi>=0.110,<1.0`），避免上游大版本破坏 API。

## 许可证汇总与结论

- 全部依赖为 **MIT / BSD-2 / BSD-3 / Apache-2.0 / PSF-2.0 / MPL-2.0**，均为宽松许可；
- **无 GPL / AGPL / SSPL** 类传染性许可，不存在"因为用了某个库就必须开源整个项目"的情况；
- `certifi` 是 MPL-2.0（文件级 copyleft），本项目未修改其源码，仅作为 CA 证书包使用，合规；
- 本项目自身为课程作业演示，不对外分发二进制，无额外合规义务。

## 被刻意拒掉的依赖

| 候选 | 为什么不用 |
| --- | --- |
| `python-jose` / `PyJWT` | 只需要 HMAC 签名会话，标准库 `hmac` + `hashlib` 十几行即可，不值得引入 |
| `pikepdf` / `pdfplumber` | `pypdf` 已够抽取纯文本；`pdfplumber` 还依赖 `pdfminer.six`（体积大、启动慢） |
| `reportlab` / `weasyprint` | 导出走**浏览器打印 CSS**（A4 794×1123px 已精确对齐），不在服务端渲染 PDF，省一个重依赖 |
| `alembic` / `SQLAlchemy` | 主数据在浏览器 localStorage，服务端只有 TTL 内存工作副本，没有持久化表结构 |
| `redis` | 单实例演示用进程内 `EventBroker`；多实例方案见 ADR 0003，未到需要它的阶段 |
| `langchain`（全量） | 只需要图执行，`langgraph` 单独装更轻；且 `langgraph` 本身可选 |
| 前端框架（React/Vue） | 三栏 + 表单 + 预览，原生 DOM 足够；无构建步骤意味着"打开就能改"，对课程作业更重要 |

## 代价

- 自己写的地方更多：SSE 流、CSRF、令牌桶、zip 安全检查、分页测量都是手写，测试压力更大；
- `pypdf` 对扫描版 PDF（纯图片）无能为力，会返回空文本 —— 已在 README「已知限制」里写明；
- 依赖上界锁定意味着半年后可能需要手动升版本。

## 检验方式

- `pip install -r requirements.txt` 后 `python -m pytest` 应全绿（76 用例）；
- 卸载 `langgraph` 后 `tests/test_workflows.py::test_dual_engine_equivalence` 会自动跳过，
  其余用例仍应全绿 —— 这是"可选依赖"承诺的实际验证方式。
